前言

控制理论有一个反差：入门很容易，用对很难。Routh 判据、Bode 图、PID 的三个参数、卡尔曼滤波的五个方程，任何一本教材都能在两小时内讲完；可把这些东西搬上一台真实的设备，往往要花掉数月。卡住人的通常不是公式，而是公式外面那层前提：对象究竟几阶、延迟有多大、执行器能给多大力、传感器能看清多小的变化、模型错了以后控制器会怎样。

一本教材与一台设备之间的距离

教材的标准写法是“已知对象，求控制器”。这句话里藏着三个不曾言明的前提：对象可以用线性时不变模型描述，模型参数是可信的，性能可以用单一标量衡量。课堂上这三个前提成立，推导便能一路走到漂亮的结论。

现场不是这样。一个回路投运之前，工程师先要回答“这台设备允许做多长的阶跃测试”，因为它可能正在生产；再要回答“这只阀门的流量特性是等百分比还是线性”，因为它决定小开度时的实际增益是标称值的几分之一；还要回答“编码器装在电机侧还是负载侧”，因为它决定背隙与柔性在不在反馈环里。这三件事答错，选再先进的方法也不会有好结果；三件事弄清楚，PID 往往就够用。工业界九成以上的回路至今仍由 PID 控制，原因不是保守，而是维护成本最低。

本书想做的就是把这两端接起来：一端是定理与算法，另一端是参数怎么定、错在哪里、怎么退回。因此每一章除了推导，都要回答四个问题——这个方法需要什么信息、参数往哪个方向调、什么时候会失效、失效时怎么降级。只有前一个问题的书是教材，只有后一个问题的书是经验汇编；两者都有的，才配得上“工程”二字。

三项写法约定

第一，正文出现的每个性能数字都来自书内脚本，读者可以在自己机器上复现。116 章各配一个可运行的 Python 仿真脚本，插图由脚本现场生成而不是从文献截图，图中的曲线、表里的数值与打印输出三者对应。这条约定带来一个副作用：书中很少出现“一般来说效果良好”这类句子，出现更多的是“在这组参数下超调 31.22%、偏差 4 s 时直接失稳”这类句子。数字可以被质疑，形容词不能。

第二，每介绍一种方法，都同时写明它的前提、参数影响方向与失效场景。控制方法没有绝对优劣，只有前提是否成立。把 LQR 用在模型准确、约束不紧的场合是浪费，把 MPC 用在模型粗糙、算力紧张的设备上是冒险；这两句话如果不写清楚，读者只会记住“MPC 更先进”这个错误印象。

第三，每章至少给一个反例，说明方法在什么条件下突然变坏。反例比正例更有信息量：正例告诉读者方法能用，反例告诉读者边界在哪里。第 47 章的 Smith 预估器在模型延迟估偏 2 s 时把超调从 0 推到 31.22%，偏到 4 s 就直接失稳；第 59 章的滑模控制里，抖振幅度近似按 kT_s 线性增长，采样周期一放大，准滑动带能把位置精度吃掉两成。这些结论都不是推出来的，是算出来的。

全书结构

全书共 116 章，分十个部分，按“工具—模型—主干—分支—应用—收束”的顺序展开。

第零部分（第 0–14 章）给数学与信号工具：拉普拉斯变换、状态空间、采样与 Z 变换、连续到离散的映射、矩阵与概率、变分法、分析力学、电机与电力电子、传感器与执行器、测量不确定度、滤波器设计。这部分不采用后面的十二节结构，只求把口径定死。

第一部分（第 15–36 章）解决“模型从哪来”：系统辨识、非参数与参数辨识、子空间与闭环辨识、非线性与时变辨识，然后是模式识别、机器学习、深度学习、神经网络、三类优化算法、强化学习与多智能体、博弈论、功能安全。这一部分有 22 章，是全书篇幅最重的一块，因为模型错了，后面所有方法都无处落脚。

第二部分（第 37–50 章）与第三部分（第 51–65 章）是两条主干：前者是经典控制，从时域指标、三类稳定性判据、根轨迹、频率响应、稳态误差、校正装置一直到 PID、串级、前馈、Smith 预估、相平面、描述函数、圆判据与 Popov 判据；后者是现代控制，从能控性与能观性、Lyapunov 稳定性、极点配置与观测器、LQR、卡尔曼滤波与 LQG、H2/H∞ 与 μ 综合、MPC、滑模、反步、自适应、随机控制、鲁棒进阶、最优控制进阶到 LMI。

第四至第六部分是三条分支：智能控制（第 66–72 章）讨论专家、模糊、神经网络、迭代学习、强化学习控制以及它们的稳定性与混合架构；前沿控制（第 73–83 章）覆盖输出分布控制、分布参数系统、事件触发、混杂系统、Koopman 算子、容错、安全控制、学习增强 MPC、全驱系统、网络化控制与量子控制；计算机控制（第 84–93 章）回到实现层，讲数字控制系统结构、实时软件、嵌入式控制器、PLC、工业通信、软件工程、数字孪生与边缘计算。

第七、第八部分是两个应用出口：运动控制（第 94–103 章）从伺服电机、运动学动力学、轨迹规划、多轴同步、机械臂、移动机器人、柔性臂与并联机构一直讲到传感器执行器与整定；过程控制（第 104–113 章）从过程建模、简单回路整定、复杂回路、多变量解耦、批次控制、软测量讲到阀门与安全仪表系统。

第九部分（第 114–115 章）做横向收束：先用统一口径与统计检验比较各类控制器的性能，再把方法摆到同一张桌子上回答“怎么选”。

各部分不是并列关系，而是层层收窄。读的时候要知道自己站在哪一层，不要把上层的算法硬套到下层还没解决的数据问题上。

怎样读这本书

116 章不是一条必须从头走到尾的直线。赶着解决现场问题的读者，先读第 0、37、41、44 章建立判断，再按对象类型跳到第 94–113 章；要做系统设计或写论文的读者，按第 1–14 章、第 51–65 章的顺序打基础；做数据驱动方向的读者，从第 15–36 章进入，但必须回头补第 37–50 章的频域直觉，否则无法判断学出来的控制器是否真的稳定。三条路径的详细章节表在第 0 章 §0.1.4 与 §0.7。

一个人很难在一年内把 116 章全部上手，但可以在一周内沿着一条路径走通一个闭环：读工具章、做一次辨识、设计一个回路、跑一遍仿真、到现场测一次阶跃。本书的结构就是为这种“走通一次”设计的。

约定

全书符号统一：r(t) 为参考输入，y(t) 为被控输出，e(t)=r(t)-y(t) 为误差，u(t) 为控制量，d(t) 为扰动，n(t) 为测量噪声，离散时刻用方括号写作 r[k]，采样周期统一用 T_s。同一符号全书只表达一个含义，遇到冲突以《术语与符号表》为准。

术语遵循国家标准：能控性、能观性、能控标准型、能观矩阵；只有讨论软件系统的可观测性、POMDP 的部分可观测，以及“可观的收益”“可控的成本”这类日常语义时才用“可”。公式只在行内与独立两种形式中出现，独立公式右侧按“章号-序号”编号，章内连续；被正文引用的公式必须存在，这条约束由构建前的自动检查保证。

仿真代码统一放在每章最后一节，公共部分调用 simlib，读者只需要看本章特有的十几行。代码用 Python 写成，依赖 numpy、scipy、matplotlib，不依赖任何商业软件。

致谢

本书的写作过程得到许多同行与现场工程师的帮助，他们提出的问题大多不是“这个定理怎么证”，而是“这个参数在我们那条线上该取多少”——正是这类问题决定了全书的取舍。书中若有错误，责任在作者，欢迎指正。
